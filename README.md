# Агент образовательных программ АЦР

ИИ-агент, который по запросу методиста собирает программу обучения по шаблонам
Академии цифрового развития и комплект материалов к ней: карту компетенций,
учебный план с точными часами, тесты с ключами, задания для семинаров, планы
лекций и слайды. Задача хакатона — в [docs/case-task.md](docs/case-task.md).

## Главный принцип

Модель отвечает за смысл, код — за числа и реквизиты.

| Делает модель | Делает код |
| --- | --- |
| цель, задачи, результаты обучения | распределение часов по модулям, темам, видам работы |
| названия модулей и тем, пропорции нагрузки | проверка сумм на всех уровнях |
| содержание тем, вопросы, задания, слайды | связь РО ↔ темы ↔ оценочные средства |
| формулировки под аудиторию | нормативная база и коды профстандартов из реестра |

Поэтому арифметика часов сходится конструктивно, а выдуманные приказы и коды
профстандартов в документ не попадают: неподтверждённое помечается
«требует проверки методистом», отсутствующее в реестре — отбрасывается.

## Быстрый старт

```bash
# офлайн-демо, без ключей и без обращения к модели
docker compose up --build
# http://localhost:3000 — интерфейс, http://localhost:8000/docs — API
```

С реальной моделью:

```bash
cp backend/.env.example .env   # заполнить LLM_API_KEY и LLM_MODEL
LLM_PROVIDER=openai_compat docker compose up --build
```

Локально без Docker:

```bash
cd backend && pip install -r requirements-dev.txt
LLM_PROVIDER=mock uvicorn app.main:app --reload --port 8000
cd ../frontend && npm install && npm run dev   # http://localhost:5173
```

## Провайдер модели

Вся работа с LLM идёт через один OpenAI-совместимый адаптер
(`app/llm/openai_compat.py`), поэтому переезд между платформами — это смена
переменных окружения, а не правка логики:

| Платформа | LLM_BASE_URL | LLM_MODEL | LLM_AUTH_SCHEME |
| --- | --- | --- | --- |
| Yandex Foundation Models (разработка) | `https://llm.api.cloud.yandex.net/v1` | `gpt://<folder-id>/yandexgpt/latest` | `Api-Key` |
| Cloud.ru Evolution FM (сдача кейса) | эндпоинт из консоли + `/v1` | например `GigaChat-Max` | `Bearer` |
| офлайн-демо | — | — | `LLM_PROVIDER=mock` |

По условиям кейса в финале допустимы только модели из каталога Cloud.ru.

## Как работает агент

Каждый шаг — отдельный навык с собственной инструкцией (`app/skills/*.yaml`),
чтобы логику можно было перенести в GigaCowork как есть.

```
запрос методиста
  └─ intake          разбор параметров, ≤5 уточняющих вопросов
       └─ skeleton   цель, РО, компетенции, модули и темы (веса, не часы)
            └─ солвер часов + автопроверка
                 └─ ГЕЙТ: методист утверждает каркас
                      └─ topic_content · tests · seminars · lecture (параллельно)
                           └─ автопроверка полного комплекта
                                └─ .docx · .pptx · GIFT/CSV · JSON
```

Точечная доработка: `POST /api/sessions/{id}/topics/{topic_id}/regenerate`
пересобирает одну тему с её тестами и заданиями, остальное не трогает.

## Автопроверка

Отчёт воспроизводит эталонные чек-листы кейса (`app/core/validate.py`):

- суммы часов: темы = модуль, ЛК+ПР+ЛБ+СРС = трудоёмкость строки, итог + ИА = заказанный объём;
- каждый РО раскрыт минимум в одной теме и проверяется минимум двумя оценочными средствами;
- нормативка и профстандарты — из реестра, неподтверждённое помечено;
- полнота обязательных разделов шаблона (свои наборы для ДПП ПК и ДОП);
- реквизиты приказа, ФИО и подписи остались пустыми;
- календарный график не противоречит объёму и ограничению часов в день.

Ошибка (`error`) блокирует переход к содержанию, предупреждение (`warning`)
уходит методисту в отчёт.

## Структура

```
backend/app/
  schemas/ir.py        ProgramIR — единый источник правды для всех выгрузок
  core/hours.py        детерминированное распределение часов
  core/validate.py     автопроверка по чек-листам кейса
  registry/legal.py    реестр нормативки и профстандартов
  skills/*.yaml        инструкции навыков агента
  pipeline/            intake → skeleton → content, разбор референсов
  llm/                 адаптер OpenAI-совместимых API + офлайн-провайдер
  render/              .docx по шаблонам АЦР, .pptx, GIFT/CSV
  main.py              HTTP API
frontend/              React + framer-motion: чат, живая сборка, отчёт проверки
reference/acr/         образцы программ АЦР и открытые запросы кейса
docs/                  задача кейса и архитектура
```

## Тесты

```bash
cd backend && python -m pytest tests -q
```

Покрыто то, что ломает приёмку: солвер часов на объёмах 16…500 ч, каждая
проверка чек-листа, сквозные прогоны открытых запросов кейса (№1, №4, №5),
включая требование не переносить арифметическую ошибку из образца стажировки.
