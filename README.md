# Агент образовательных программ АЦР

Методист пишет «программа повышения квалификации на 72 часа по анализу данных
для сотрудников банков» — агент возвращает готовый комплект: программу в .docx
по шаблону Академии, учебный план с часами, карту компетенций, тесты с ключами,
задания семинаров, планы лекций и слайды.

Задача хакатона — [docs/case-task.md](docs/case-task.md).

## Главное решение

Модель пишет тексты. Числа считает код.

Часы распределяет солвер, а не модель: суммы по темам, модулям и видам работы
сходятся с заказанным объёмом конструктивно, а не по удаче. Нормативные акты и
коды профстандартов берутся из реестра — чего там нет, в документ не попадает,
неподтверждённое помечается «требует проверки методистом».

Модели отдают строку вместо объекта, забывают форму обучения, недодают
вопросов, требуют практику там, где аудиторных занятий нет. Каждый такой
случай закрыт кодом и тестом: `tests/test_model_discipline.py`,
`tests/test_intake_without_model.py`.

## Запуск

```bash
docker compose up --build          # http://localhost:3100, офлайн-демо без ключей
```

С реальной моделью — ключ в `.env` рядом с `docker-compose.yml`:

```
OPENAI_API_KEY=...
OPENAI_BASE_URL=...
OPENAI_MODEL=GigaChat/GigaChat-3-Pro
```

Без docker compose:

```bash
make deploy                        # собирает два образа и поднимает на 8000
make logs                          # логи бэкенда
make stop
```

Для разработки:

```bash
cd backend && LLM_PROVIDER=mock uvicorn app.main:app --reload --port 8000
cd frontend && npm install && npm run dev
```

## Переменные

| Переменная | Зачем |
| --- | --- |
| `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL` | доступ к модели; `LLM_*` тоже принимаются |
| `LLM_PROVIDER=mock` | офлайн-заглушки, без сети и без денег |
| `LLM_MAX_PARALLEL` | одновременных запросов к шлюзу (площадка держит 2) |
| `LLM_CACHE=1` | повторный одинаковый запрос берётся с диска — режим отладки |
| `WEB_PORT` | порт интерфейса |

Провайдер один, OpenAI-совместимый: смена платформы — это смена переменных,
а не правка кода. Проверено на Yandex Foundation Models и Cloud.ru.

## Как устроен путь

Каждый шаг — отдельный навык со своей инструкцией в `app/skills/*.yaml`.

```
запрос методиста
  intake      разбор параметров, не больше 5 уточняющих вопросов
  skeleton    цель, результаты обучения, компетенции, модули и темы
  солвер      часы по модулям, темам и видам работы + автопроверка
  ────────── методист утверждает каркас ──────────
  content     содержание тем, тесты, семинары, планы лекций, слайды
  автопроверка полного комплекта
  выгрузки    .docx · .pptx · GIFT · CSV · JSON
```

Пересборка одной темы, без остального комплекта:
`POST /api/sessions/{id}/topics/{topic_id}/regenerate`.

## Автопроверка

`app/core/validate.py`, 18 кодов:

- суммы часов на всех уровнях, включая итоговую строку с аттестацией;
- каждый результат обучения раскрыт темой и проверяется двумя оценочными средствами;
- источники и профстандарты существуют;
- разделы шаблона заполнены (свои наборы для ДПП ПК и общеразвивающей);
- реквизиты приказа, ФИО и подписи остаются незаполненными;
- календарный график не противоречит объёму.

Ошибка блокирует переход к содержанию, предупреждение уходит в отчёт методисту.

## API

Интерфейс ходит по шагам (`/api/sessions/...`), для машинной проверки есть один
вход:

```bash
curl -X POST localhost:8000/api/generate -H 'Content-Type: application/json' \
  -d '{"text": "программа повышения квалификации на 72 часа по анализу данных на Python для сотрудников банков, очно-заочно, защита проекта"}'
```

Данных хватает — придёт `status: "ready"` с программой, отчётом и ссылками на
выгрузки. Не хватает — `status: "need_answers"` с вопросами; ответы досылаются
вторым вызовом на тот же адрес с `session_id`.

## Проверки

```bash
cd backend
python -m pytest tests -q                   # 94 теста, заглушки, без сети
python scripts/run_open_requests.py         # 5 запросов кейса с чек-листами
```

Тесты изолированы от окружения: ключ в терминале не уведёт их в живую модель.

Отладка без обращений к модели:

```bash
python scripts/replay_model_answer.py --case 2 --drop study_form --skeleton
python scripts/probe_parallel.py --levels 1 2 4
```

Первый прогоняет запрос на заранее заданном ответе модели, второй измеряет,
сколько одновременных запросов пускает шлюз.

Собрать комплект файлами, без браузера:

```bash
python scripts/generate.py --type pk --hours 72 --title "Анализ данных" --out ../out
```

## Что внутри

```
backend/app/
  schemas/ir.py     структура программы — источник правды для всех выгрузок
  core/hours.py     распределение часов
  core/validate.py  автопроверка
  registry/legal.py реестр нормативки и профстандартов
  skills/*.yaml     инструкции навыков
  pipeline/         intake → skeleton → content
  llm/              адаптер OpenAI-совместимых API, заглушка, кэш
  render/           .docx, .pptx, GIFT, CSV
frontend/           чат, живая сборка, отчёт, статистика
data/acr/           материалы кейса: образцы программ и запросы для проверки
docs/               задача кейса и архитектура
```

## Статус

Работает: оба шаблона АЦР, уточняющие вопросы, каркас с точными часами, карта
компетенций, тесты, семинары, лекции со слайдами, автопроверка, выгрузки,
точечная доработка темы, учёт токенов и стоимости.

Не сделано: Moodle XML, разбор .pptx на входе, актуализация старой программы,
адаптация под другую аудиторию и объём.
